# Telegram — пакет Quadro Hub (`quadro.telegram`)

ИИ владельца, подключённый к MCP Hub, читает выбранные им чаты Telegram — с файлами, картинками и ссылками. Только чтение.
Сделан путём стороннего автора: свой проект вне ядра Hub, публичный SDK, подписанный пакет, Каталог.

## Как устроено

- **Часть на ПК** (`pc/`, Node, `@quadrohub/pc-sdk`): клиент MTProto — teleproto (MIT, живой форк GramJS), вшит esbuild в
  `dist/pc/part.cjs`. Вход от аккаунта владельца, как обычный клиент («Quadro Hub» в «Настройки → Устройства»): по QR-коду
  с телефона (по умолчанию) или по номеру, код и облачный пароль.
  - Сеть — только через программу: свой `WebSocketTransport` teleproto поверх `host.net.websocket` к
    `wss://*.web.telegram.org/apiws` (адреса Telegram Web), право `net:*.web.telegram.org`. Свои `net`/`tls`/`http`/`socks`
    у части закрыты, в сборке это заглушки (`scripts/build-pc.mjs`).
  - Без кода, созданного на лету: `new Function` teleproto в сборке заменён отказом, работает его запасной разбор
    (проверка Каталога иначе отправляет пакет человеку). Тест `test/tl-fallback.test.ts`. Нативный модуль шифра
    (`cifrante`) не подгружается (`pc/env.ts`).
  - Сессия, api_id и api_hash — в папке данных части, запечатаны Windows (`host.secrets`, DPAPI). На сервер Hub переписка
    не уходит и там не хранится. Программа без `host.secrets` — ничего не сохраняется, экран просит обновить программу.
  - Пределы: страница до 300 сообщений (по умолчанию 100), текст сообщения до 4000 знаков, ответ до ~300 КБ текста,
    поиск до 200, картинка до 8 МБ, текстовый файл до 2 МБ, файл на ПК до 50 МБ; каждый вызов Telegram — до 45 с.
- **Экран** (`src/`, React по шаблону qhapp-react, мост `quadro.js`): ключи с my.telegram.org по шагам → вход (телефон, код,
  облачный пароль — вводит сам владелец; или QR-код с телефона) → «Доступ для ИИ» (по умолчанию ни один чат) → «Что читал ИИ» (журнал, без
  содержимого) → «Аккаунт» («Выйти из Telegram» — закрывает сессию в Telegram и удаляет с ПК).
- **Инструменты ИИ** (`manifest.json` → `mcp.tools`, handler `pc:<имя>`, право `pc.mcp`; Hub добавляет приставку `telegram_`):
  `telegram_chats`, `telegram_messages` (период, страницы, `cursor`), `telegram_search`, `telegram_file` (картинка — как
  изображение, текст и .docx — текстом, остальное — превью и путь на ПК). Только разрешённые чаты; методы экрана ИИ не
  достаются, а инструменты ИИ — экрану (`host.rpc.handle` и `host.mcp.handle` разные).
- **Экран «Работы и оплата» в чате ИИ** (1.4.0, MCP Apps, kernel.md §12е): `views.works` (`surface: mcp-app`,
  `public/works.html` — один HTML, встроенный скрипт без сборки) у инструмента `telegram_search` (`view: works`).
  - Ответ поиска несёт `data` (`pc/works.ts`): у каждого найденного сообщения чат, кто, текст, сумма, «оплачено?» и
    ссылка `https://t.me/…`. Hub отдаёт это экрану как `structuredContent`, до 30 000 знаков JSON.
  - Сумма и «оплачено?» — догадка по словам: «оплатил», «скинул 700 ₽» — да; «жду оплату», «оплачу в пятницу»,
    «оплатил?» — нет. Ответ «оплатил» на найденную работу отмечает её.
  - Ссылка: публичный чат и супергруппа — на само сообщение, личный чат с @именем — на чат; маленькая группа и личный
    чат без @имени — без ссылки (Telegram их не даёт).
  - Таблица «чат · кто · что за работа · сумма · оплачено?» с фильтрами и кнопкой «Открыть в Telegram»; в узком чате —
    карточки.
  - Человек ищет на экране сам (поле, быстрые слова, чат): в чате ИИ — `tools.call('search')`; в Hub — метод части
    `search`, то есть поиск от лица человека, без строки в «Что читал ИИ». Список чатов в чате ИИ — `telegram_chats`, в
    Hub — `access`.
  - В чате ИИ кнопка «Попросить ИИ проверить неоплаченные» (`quadro.ai.send`) отправляет ему список.
  - `mcp.instructions` говорят ИИ, как искать неоплаченные работы и что проверять по переписке. Права — как в 1.3.0.

## Выгрузка из Telegram Desktop — без ключей и без входа (1.4.1)

Когда my.telegram.org не выдаёт ключи, человек загружает выгрузку переписки из Telegram Desktop:
⋮ в чате → «Экспорт истории чата» → формат «Машиночитаемый JSON» → файл `result.json`.
- **Почему файл читает экран, а не часть.** Часть на ПК запущена в песочнице Node (`--permission`, читать — только свои
  папки), а у программы нет вызова «прочитать выбранный файл» (`files.pick` даёт только путь). Экран читает выбранный
  `result.json` средствами браузера на этом ПК и передаёт текст части кусками по 4 млн знаков (`importStart` /
  `importChunk` / `importEnd`). Новых прав нет.
- **Разбор** (`pc/export.ts`):
  - форматы — один чат (`{ name, type, id, messages }`) и все данные (`chats.list`, `left_chats.list`);
  - id чатов — как у живого клиента (`-100…` супергруппы и каналы), поэтому работают ссылки t.me/c;
  - берутся текст со ссылками, ответы, пересылки, служебные строки и вложения (имя, размер, путь в папке выгрузки);
  - HTML-выгрузку и чужой файл отклоняет словами.
- **Хранение.** Чаты хранятся в `exports.bin` папки приложения, запечатанные Windows, как сессия. Чат, выгруженный
  снова, заменяет старый. На сервер Hub ничего не уходит.
- **Доступ.** Чаты выгрузки попадают в «Доступ для ИИ» закрытыми.
- **Инструменты ИИ.** Читают их без Telegram и пишут «по выгрузке от ДД.ММ.ГГГГ»:
  - `telegram_messages` без периода берёт последние 30 дней выгрузки;
  - `telegram_file` говорит, что за файл и где он лежит, но не открывает его;
  - таблица «Работы и оплата» несёт `exportedAt`.
- **Экран:**
  - рядом с ключами и входом — «Нет ключей или не получается войти? → Загрузить выгрузку»;
  - без входа — «Без входа — по выгрузке…» и кнопка «Войти в Telegram»;
  - вкладка «Выгрузка»: загрузить ещё, убрать чат, убрать всё.
- **Когда в программе появится чтение выбранного файла** (`files.read`), часть сможет читать `result.json` с диска сама,
  без копии.

## Собрать и проверить

```bash
npm install
npm run build          # пакет целиком (с инструментами ИИ)
npm run build:no-mcp   # без mcp и pc.mcp — для Hub старше 20.11.2026
npm test               # сервис на заглушке Telegram, собранная часть (IPC, сокеты программы), сокет, ссылки, даты
npm run typecheck
```

Экран без публикации — своя копия Hub (`HUB_DEV_PACKAGES="<эта папка>" node scripts/dev.mjs --addr apps.localhost …`) и
скрытый зонд Hub (`apps/desktop/scripts/probe.cjs`), настоящий Telegram не трогается:
- `test/probe-telegram.cjs` — экран целиком на заглушке части;
- `test/probe-relay.cjs` — путь ИИ целиком: режим автора (часть из `dist/`), «ИИ может пользоваться», ключ с пакетом,
  MCP `tools/list` и `tools/call telegram_*` через Hub и мост до части на ПК (`--bridges --apps`, `QUADRO_DEV_PACKAGES`,
  `QUADRO_PROBE_RELAY=1`);
- `test/probe-export.cjs` — выгрузка без ключей целиком: настоящая часть в режиме автора, `test/fixtures/result-chat.json` в
  поле файла, доступ, MCP `telegram_chats` / `search` / `messages` с пометкой «по выгрузке», журнал, «Убрать все выгрузки»;
- `test/probe-works.cjs` — экран «Работы и оплата» в Hub (тот же HTML): поиск через метод части `search`, таблица,
  список чатов (заглушка части, `PROBE_DATA` — JSON настоящего `worksData`); `probe-relay.cjs` проверяет и сторону чата
  ИИ: `_meta.ui.resourceUri` у `telegram_search`, `resources/read ui://telegram/works`, строку пакета в `instructions`;
- `test/probe-quadro-keys.cjs` — экран с ключами Quadro и без них (заглушка части);
- `test/probe-publisher-dev.cjs` — настоящая часть в режиме автора с выдуманными `dist/publisher.dev.json`: экран без шага
  ключей, Telegram отказывает выдуманным ключам, api_id издателя на экране нет. После проверки файл удалить.

pc-sdk — как в документации автора: `npm i -D https://quadro-metaverse.site/pkg-sdk/v1/pc-sdk-0.1.0.tgz`.

## Упаковать и подписать

```bash
npm run check:dist     # в dist/ нет значений издателя и ключей
npm run qhapp -- pack "<эта папка>/dist" --out "<эта папка>/out/quadro.telegram-1.0.0.qhapp" --key ~/.quadro/keys/quadro-1.key --kid quadro-1
npm run qhapp -- check "<эта папка>/out/quadro.telegram-1.0.0.qhapp" --publisher quadro --trust official --key quadro-1=<открытый ключ>
```

## Ключи Telegram (api_id, api_hash)

- **Ключи Quadro** (издателя) — как у всех сторонних клиентов: человек сразу входит по QR. В пакете их нет и быть не может:
  пакет публичный, а опубликованный api_hash Telegram ограничивает у всех (`API_ID_PUBLISHED_FLOOD`).
  - Манифест объявляет `publisherValues` `api_id` и `api_hash` (`for: ["pc"]`), значения задаёт издатель в Каталоге —
    они хранятся запечатанными и меняются без новой версии (ядро §12б).
  - Программа берёт их перед стартом части и кладёт в `host.app.config.publisher` (`publisherKeysOf` в `pc/publisher.ts`).
  - Telegram не принял ключи Quadro (`API_ID_INVALID`, `API_ID_PUBLISHED_FLOOD`) — экран говорит «Ключи Quadro не подошли» и
    предлагает свои; у своих ключей — слова Telegram как есть.
  - Режим автора: `dist/publisher.dev.json` (`{ "api_id": "…", "api_hash": "…" }`) — только для проверки;
    `npm run check:dist` не даст упаковать dist/ с ним.
- **Свои ключи** с my.telegram.org — запасной путь («Аккаунт → Дополнительно», ссылка на шаге входа); подсказки при «ERROR» и
  «Too many attempts» — на экране ключей.
- Сессия помнит, с какими ключами создана: смена ключей издателя не ломает вход.
